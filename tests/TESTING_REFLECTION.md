# Testing Reflection

Throughout the testing process for the Campus Resource Hub application, I discovered that different testing styles revealed distinct types of defects. Unit tests focused on small, isolated functions like `allowed_file()` and `has_conflict()`, exposing edge case handling issues such as the function failing with invalid input types (None, integers) and confirming that pending bookings correctly don't cause conflicts. Integration tests validated interactions between controllers, models, and the database, revealing issues with CSRF token handling in test requests and ensuring the complete booking flow works end-to-end. Manual testing uncovered user experience issues that automated tests missed, such as error messages not being user-friendly and navigation flows that could confuse first-time users.

AI tools like Cursor were instrumental in generating test structure and suggesting edge cases, significantly speeding up initial test setup. However, they sometimes generated tests that didn't match actual application behavior, requiring careful review. There was also a tendency to over-rely on AI-generated tests without thoroughly validating they tested the intended functionality. Moving forward, I would improve test coverage by adding more edge case and error handling tests, implement better test data management using reusable fixtures, and ensure complete test isolation to prevent interdependencies. While AI tools accelerated development, maintaining a critical eye and manually verifying test correctness proved essential for ensuring the test suite actually validates the application's behavior.
